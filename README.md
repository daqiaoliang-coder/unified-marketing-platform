# 统一营销平台（VMP）

> 面向电商交易的统一营销与优惠底层体系，覆盖营销玩法接入、统一出价、优惠计算编排、优惠资源管理及订单生命周期中的营销业务流转。

本仓库基于个人项目经历整理业务能力与核心架构，作为技术经验展示，不包含原业务系统源码，也不代表可直接部署的开源实现。

## 1. 平台定位

VMP 承载微店营销体系，为不同营销玩法提供统一的优惠底层能力，连接商品展示、交易询价、下单及订单后续流转。

- **商品详情页**：提供统一出价接口，统一承接营销优惠的价格展示需求。
- **交易询价**：完成优惠计算、活动组合与价格处理。
- **交易下单**：承接优惠快照持久化、优惠资源扣减与锁定。
- **订单流转**：通过优惠快照衔接同步回滚与异步营销业务处理。

## 2. 业务能力

| 业务目标 | 营销玩法 |
| --- | --- |
| 拉新 | 秒杀、拼团 |
| 复购 | 复购券、定向优惠 |
| 提升客单价 | 优惠套餐、满减 |
| 促进成交 | 限时折扣、满减及其他优惠工具 |

这些玩法共享优惠计算与交易处理能力，而不是各自维护完整的交易优惠链路。

## 3. 两大核心接口

| 接口 | 核心职责 | 关键机制 |
| --- | --- | --- |
| **读接口：优惠计算** | 计算订单可用优惠及其组合，处理价格与金额分配 | 计算编排、叠加、排他、排序、均摊、各方分润 |
| **写接口：优惠执行** | 将优惠计算结果衔接到下单与订单生命周期 | 优惠快照、资源扣减与锁定、分布式事务、同步回滚与异步流转 |

读接口关注“优惠如何计算与组合”，写接口关注“优惠如何执行，以及订单变化后如何继续处理或回滚”。

## 4. 读接口：优惠计算与编排

### 4.1 核心构成

| 构成 | 作用 |
| --- | --- |
| 查询计划、过滤器 | 组织优惠相关数据查询，并过滤候选数据或活动 |
| Callback 回调层、Callable 取数 | 衔接优惠计算所需的数据与回调处理 |
| 优惠计算编排 | 组织活动挂载、组合生成、叠加与排他、排序及金额处理 |
| 插件、插件过滤器 | 过滤参与执行的优惠插件，并承载具体优惠计算 |
| 优惠工具执行引擎 | 根据条件元数据与配置元数据，产出结果元数据 |

执行引擎以元数据描述优惠工具的计算输入与输出：

```text
条件元数据 + 配置元数据 → 结果元数据
```

### 4.2 主计算链路

```text
查询计划 / 过滤器 / Callback 回调层
                  ↓
           从 Callable 中取数
                  ↓
     将可能参与计算的优惠活动挂载到订单
                  ↓
          针对每个订单计算叠加组合
       ├─ 自叠加
       ├─ 优惠活动类型叠加
       └─ 叠加 / 排他规则约束
                  ↓
       针对每个叠加组合计算笛卡尔积
                  ↓
     将笛卡尔积中的每个元素作为优惠组合
                  ↓
      每个优惠组合经插件过滤与插件计算
                  ↓
         更新子订单实付款，继续计算
                  ↓
        汇总计算结果与金额分配结果
```

### 4.3 优惠组合计算

优惠计算不只是执行单个活动，而是处理多个活动在订单上的组合关系：

1. **挂载候选活动**：将可能适用的优惠活动关联到订单。
2. **计算叠加关系**：区分活动自叠加与不同优惠活动类型之间的叠加，并处理排他约束。
3. **生成候选组合**：针对每个叠加组合计算笛卡尔积，将其中每个元素展开为具体优惠组合。
4. **执行组合计算**：通过插件对每个优惠组合进行优惠计算。
5. **处理排序与金额分配**：在计算编排中处理排序、优惠均摊及各方分润。

排序、均摊、分润属于整体计算能力；这里不将其限定为所有玩法都完全一致的固定执行顺序。

### 4.4 子订单与主订单的计价关系

订单之间的优惠计算存在基准价依赖：每计算下一个订单前，需要更新子订单实付款，用于后续主订单基准价计算。

```text
子订单优惠计算 → 更新子订单实付款 → 主订单基准价计算 → 后续优惠计算
```

这一关系意味着计算编排必须关注订单层级与执行顺序，不能将各订单的优惠计算简单视为彼此独立。

## 5. 写接口：快照、资源与分布式事务

### 5.1 下单同步处理

订单下单时，先保存优惠快照，再通过 `dealPromotionAfter` 执行后续优惠处理，承接优惠资源扣减等同步操作；优惠资源锁定也属于平台写侧能力。

```text
交易下单 → 保存优惠快照 → dealPromotionAfter → 同步优惠处理 / 资源扣减
```

优惠快照为后续订单流转与回滚提供优惠处理上下文。

### 5.2 订单流转后的异步处理

订单状态流转后，通过异步消息与优惠快照驱动营销业务：先查询快照，再调用 `dealPromotionAfter` 进行相应处理。

```text
订单流转 → 异步消息 → 查询优惠快照 → dealPromotionAfter
                                             ├─ 优惠回滚
                                             ├─ 满送
                                             └─ 赠金币等业务
```

### 5.3 TCC 同步回滚

分布式事务场景下，TCC 同步回滚同样基于优惠快照恢复处理上下文，再进入 `dealPromotionAfter` 执行回滚。

```text
TCC 同步回滚 → 查询优惠快照 → dealPromotionAfter → 优惠回滚处理
```

### 5.4 写侧处理路径汇总

| 触发场景 | 快照操作 | 处理入口 | 业务职责 |
| --- | --- | --- | --- |
| 下单同步处理 | 先保存快照 | `dealPromotionAfter` | 同步优惠处理、优惠资源扣减 |
| 订单流转异步消息 | 先查询快照 | `dealPromotionAfter` | 优惠回滚、满送、赠金币等 |
| TCC 同步回滚 | 先查询快照 | `dealPromotionAfter` | 分布式事务中的同步优惠回滚 |

三条路径共享快照与处理入口，但触发时机和业务语义不同，不能将异步业务流转与 TCC 同步回滚混为同一条链路。

## 6. 核心设计要点

- **统一营销底座**：以共享的计算与写侧能力承接拉新、复购、客单价提升和促成交等营销需求。
- **优惠组合编排**：将叠加、排他和笛卡尔积组合计算纳入统一流程，处理多活动并存的复杂性。
- **插件化与元数据驱动**：由插件承载具体优惠计算，以条件元数据、配置元数据和结果元数据组织优惠工具执行。
- **订单层级感知**：将子订单实付款更新与主订单基准价计算纳入编排，保持计算依赖明确。
- **计算与执行职责分离**：读侧负责优惠与金额计算，写侧负责快照、资源处理及订单后续流转。
- **快照驱动的生命周期处理**：以优惠快照连接下单执行、异步营销业务与 TCC 同步回滚。
